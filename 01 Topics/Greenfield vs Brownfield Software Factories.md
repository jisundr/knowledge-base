# Greenfield vs Brownfield Software Factories

Where to point an [[Autonomous Software Factory]]: at **brownfield** systems, not **greenfield** ideas.

- **Greenfield** work is discovery. You do not yet know what the customer wants, so automating production just builds the wrong thing faster, spends more, and adds bloat. Use discovery techniques ([[Problem-First Thinking]], [[Four Big Product Risks]]) until product-market fit.
- **Brownfield** work is existing software that customers already pay for and use. Runtime data, user behavior, and support tickets supply the requirements and the feedback, so a factory can keep the system stable without inventing what to build.

A brownfield factory can also rewrite legacy code, so technical debt and backlogs shrink, and it frees time for greenfield discovery. The source estimates about a week to stand one up over existing commitments.

Rule of thumb: automate keeping existing [[Software Promises]], not guessing new ones.
