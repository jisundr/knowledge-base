# Problem-First Thinking

Start from the customer problem, not the feature. A **solution-first** team asks "What should we build?". A **problem-first** team asks "What customer problem are we solving, why does it matter, and how will we know the pain decreased?".

The failure it prevents is **product myopia**: committing to a feature or UI mockup before the underlying pain is validated. With AI coding agents this gets worse, because the wrong solution now ships faster and piles up technical debt sooner.

## Signals of unaddressed pain

- Friction is silent: users rarely file tickets for a confusing flow, they leave.
- **Workarounds** (side spreadsheets, manual exports) are product signals, not user quirks.
